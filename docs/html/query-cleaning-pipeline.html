清洗与标注流程

输入aime/input.jsonl · iwencai/chat.jsonl 最终产物cleaned_queries.jsonl（hard + normal）
  1. preclean 输入清洗 格式嗅探 · 坏行 · 去重
  2. segment 会话分段 LLM · 主题切 2–4 段
  3. rule_gate 候选筛选 规则 · 噪声拒绝 + 工具门槛
  4. judge 语义判定 LLM · value→complexity→classify
  5. verify 独立复判 LLM · hard 5 轮 / normal 2 轮
  6. answer_gate 回答质量门 规则 · 完成态 / 非拒绝 / ≥50 字
  7. post 去重与翻译 规则 + LLM · 模板合并 + 译简中
  8. ✓ 进入样本 accepted
value_rejected 无保留价值
failed LLM 失败丢弃 rejected 复判与难度相悖 rejected 回答不完整 / 拒绝话术 rejected 重复样本合并

双分类体系

复杂问句（hard）归 9 类，输出 complex-topic/{id}-{slug}；非复杂但有价值的问句（normal）归 16 类，输出 {id}-{slug}。两套 id 各自从 01 起编，靠 difficulty + 前缀区分。分类数据源：templates/categories.md（清单）+ complex_few_shot.md / normal_few_shot.md（定义与示例），改分类只动模板不动代码。

复杂 9 类 · difficulty=hard

编号 / slug 分类 特征 代表问句
01complex-topic/01-data-metrics-calculation
复杂取数计算
特征需要多指标/多条件组合筛选、回测策略、统计规律挖掘、技术形态的量化描述，或多步骤数据处理。核心是「算」——不是简单查一个数，而是通过计算框架得出结果。常见要素：均线/换手率/量比/涨跌幅等指标阈值组合、回测区间与买卖规则、跨时间段的统计对比、多因子叠加。
代表「回测一个基于5周均线的短线择时策略，比较其与沪深300指数的超额收益。回测区间2021年1月1日至2026年4月30日，股票池全部A股剔除ST/北交所/上市不满…」
02complex-topic/02-forecasting-and-projection
预测类
特征以时间维度推演为核心——预测未来股价/业绩/事件走向，或推演不同场景下的结果。关键信号词：「预测」「目标价」「能涨到多少」「什么时候」「概率」「极端场景」「剧本」。常见要素：目标价位、时间窗口、概率分布、多场景推演、极端条件假设。
代表「中际旭创未来1年股价能涨到多少？」
03complex-topic/03-analysis-research
分析研究
特征以深度理解为目标——多维度框架分析、产业链/政策/宏观深度研究、因果关系解释、综合研判。关键信号词：「分析」「研究」「为什么」「影响」「框架」「产业」「政策」。常见要素：基本面/技术面/情绪面/资金面等多框架、产业上下游拆解、政策传导逻辑、历史对比。
代表「美伊何时能达成停火协议，结合历史战争事件分析市场走势。」
04complex-topic/04-opportunity-discovery
机会挖掘
特征以发现交易机会为目标——事件驱动、热点主题、板块轮动、龙头识别、潜在高弹性标的。关键信号词：「找出」「挖掘」「龙头」「翻倍」「涨停」「机会」「热点」「哪只」。常见要素：事件催化+受益标的映射、板块龙头识别、涨停原因分析、资金流向跟踪、主题扩散路径。
代表「从目前热点中找出未来1-3月可能翻倍的标的，并说明逻辑。」
05complex-topic/05-asset-allocation
资产配置
特征以资金分配为核心——组合构建、仓位比例设计、跨资产/跨市场配置、投资期限匹配、个性化约束（年龄/收入/风险偏好/流动性需求）。关键信号词：「配置」「组合」「仓位」「分配」「多少比例」「分散」「资产」「规划」。常见要素：资金规模、投资期限、风险偏好、资产类别选择、比例分配。
代表「我有200W美金，我想买一些存储相关得标的，我希望你根据MVP现代投资理论给出我具体策略构建逻辑。」
06complex-topic/06-investment-decision
账户诊断优化类
特征以已有持仓/账户为出发点——审视现有组合、给出买卖点/仓位调整/风控建议、选股策略优化。关键信号词：「持有」「持仓」「账户」「补仓」「减仓」「止损」「优化」「怎么处理」「帮我看看」。常见要素：具体持仓标的和成本、账户总资产、目标收益、交易风格、时间约束。
代表「搜索今天所有强势的股票，主要是主板，结合龙虎榜，有哪些是上面这些砸盘王，比如知春路、紫阳东路、成都系这些砸盘王持有的股票，我想排雷。」
07complex-topic/07-strategy-evaluation
策略触发任务类
特征以条件→动作为核心——设定规则，当行情/价格/事件满足条件时自动触发提醒或执行。关键信号词：「如果……就」「当……时」「触发」「提醒」「alert」「条件」「规则」「异动」「监控」。常见要素：触发条件（价格/均线/量/事件）、执行动作（买入/卖出/提醒）、持续监控要求。
代表「这个图片里是我的持仓，你把它记住了。每天都有问题的时候，有基本面出问题或者出现什么意外的事情，你提醒我，并且如果要发现哪个股票更好，可以替代其中的一个也告诉我。」
08complex-topic/08-goal-execution
目标跟踪执行
特征以长周期目标为驱动——设定长期收益目标，需要持续跟踪、动态调仓、阶段性复盘、通知确认。关键信号词：「长期」「年化」「跟踪」「持续」「动态」「季度」「定期」「目标收益」。常见要素：年化收益目标、投资期限、调仓频率、通知方式、里程碑检查。
代表「—」
09complex-topic/09-action-output
动作类
特征以明确的工具操作或交付物为终点——生成报告、导出文件、发送通知、创建仪表盘、可视化等。关键信号词：「PPT」「Excel」「邮件」「dashboard」「报告」「导出」「生成」「建一个」「发」「写一个」。常见要素：输出格式（PPT/Excel/PDF/dashboard）、发送方式（邮件/通知）、内容要求。

分类提示词 classify_complex / classify_normal · 动态组装 
两个分类提示词不写死在代码里，构建时由模板动态组装（src/query_pipeline/prompts/assemble.py）：

头部固定规则：
你是一个金融问句分类器。给定一个**已判定为复杂金融问句**的问句（附前文问题列表，仅用于消解指代），从下列 9 类中选择**唯一**类别。
- 只按问句意图归类，不按关键词机械匹配。
- 若多个类别都沾边，选择最决定答案正确性的那一类。
- 只输出严格 JSON，不要 Markdown：{"category_id": "01", "reason": "中文短句，说明归类理由"}
- category_id 必须是下列 9 类之一。

（normal 版头部同上，16 类；category_id 必须是下列 16 类之一）

类别正文 = templates/categories.md（9 类清单）
          + templates/complex_few_shot.md（每类特征 + 示例，最多 1000 条）
          + templates/normal_few_shot.md（每类定义/适用场景/排除场景/边界规则/易混类别）

改分类体系 = 改 templates/ 下的 md 文件，代码与提示词无需改动。
会话分段提示词 segment · LLM 
你是一个金融客服会话切分专家。给定一个会话中按时间顺序排列的用户问句（已编号 0,1,2,...），请从宏观角度把问句划分为少数几个大的会话主题段。

核心要求（宏观优先，避免细碎）：
- 一定要从整体/宏观视角切分：整个会话通常只划分为 2-4 个大主题段，不要超过 4 段。
- 宁可合并过度，也不要拆分过细：相邻的相似小主题必须合并为一段，只有主题发生明显、重大的切换时才开新段。
- 不要把一个大主题拆成多个小段，也不要为个别问句单独分段。
- 尽量避免产生只有 1 个问句的片段：单问句通常并入相邻片段，除非它是明显独立、与前后问句都无承接的新主题。
- 每个问句属于且仅属于一个片段；片段按顺序连续、互不重叠地覆盖全部问句。
- 同一个主题不能再次出现：如果某主题在后面又出现了，应把它并入第一次出现所在的片段。
- 主题名用简短中文（4-12 字），如“行情复盘”“选股策略”“持仓诊断”。

输出要求：
- 只输出一个可解析的裸 JSON 对象，不要输出 Markdown、代码块或任何说明。
- start/end 是问句编号，含两端；第一段 start=0，最后一段 end=总问句数-1，且 segments[i].start = segments[i-1].end + 1。

JSON 格式：
{"segments":[{"start":0,"end":5,"topic":"..."}, {"start":6,"end":9,"topic":"..."}]}
价值门提示词 value_gate · LLM 
你是一个金融问答数据的价值判官。给定一段会话中、目标问句之前的所有用户问句（前文，可能为空），以及目标问句本身，判断该问句**是否有保留价值**。

判为无价值（is_valuable=false）的情形：
- 纯闲聊、寒暄、情绪表达、与金融无关的话题（天气、新闻闲聊、无关个人话题等）。
- 无任务输出：纯陈述/状态播报/数据转述/计划告知（只汇报行情、持仓、价格、涨跌、已做的交易或接下来的安排，不含任何任务），抱怨/质疑/复盘纠偏，纯确认（"好的""可以""继续"）。
- 非金融问题：与证券投研、投资决策、金融产品、上市公司、市场分析无关。
- 依赖不可见上下文才能成立：主体、任务或关键约束必须靠前文（或前文之外看不到的历史）补全，句内无法自解释；纯承接性短指令（"继续""再看看""那这几只呢"）。

判为有价值（is_valuable=true）的情形：
- 句内对象与任务明确，即使很短、啰嗦或拼写差，但可独立理解。
- 前文列表仅用于理解指代；只要句内线索足够恢复主体与任务，就不算依赖不可见上文。

输出要求：
- 只输出一个可解析的裸 JSON 对象，不要 Markdown、代码块或说明。
- 字段：{"is_valuable": bool, "reason": "中文短句，说明判定理由"}
复杂度门提示词 complexity_gate · LLM
